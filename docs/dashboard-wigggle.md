# Wigggle widget replacement

Open Home → Add widget → Wigggle designs. The catalogue contains all 92 source designs from [Wigggle UI](https://wigggle-ui.vercel.app/), grouped into clock, calendar, weather, media, productivity, dashboard, stocks and sports. Every supported upstream size is included.

The designs replace the previous Kokonut addition. Home uses the adapted Wigggle Widget primitive and shared shell. Menus use the app's accessible, portalled menu; size choices are visible radio buttons, and selecting Medium no longer forces a Glance card back to Small. Collapsing frees the card's grid tracks and expanding restores the content without discarding its state.

Choose **Apply to** for a widget already on Home, or **Add** for a compatible source. This changes that widget's saved `design` and size, rather than creating an additional copy. The existing SQLite layout stores the optional design ID. Existing layouts without a design continue to work. Unknown design IDs are rejected by the API.

Catalogue previews are explicitly labelled **Sample data**, inert, and separate from the live widget registry. The original upstream examples include demonstration prices, scores, songs, alarms and tasks. They never replace real widget payloads. Browsing weather samples uses local fixtures and never requests location or contacts a weather service. Local reference artwork is namespaced under `public/wigggle/assets`.

Home continues to use its existing providers and permission-gated actions. The clock tile renders nine purpose-built faces from live browser time and saved zones: three digital faces (`clock-sm-01`–`03`), three analog faces (`04`–`06`) and three world-clock faces (`07`–`09`). The default is `clock-sm-01` (Minimal digital). The Wigggle catalogue remains available for reference previews; applying a clock design ID selects the matching custom face. All 11 weather designs use the existing Open-Meteo provider: current temperature, humidity, feels-like temperature, wind, precipitation and conditions; 12 hourly readings; and seven daily forecasts. Missing measurements remain unavailable rather than using sample values. Calendar month compositions mark only events in the cached provider results, not availability beyond those results. Other compatible designs adapt the corresponding existing source and controls. Stock/sports designs, airfare pricing, stopwatch/alarm-picker designs, and media/device controls without a provider remain design samples; their examples cannot be added as fake live data.

Use **Setup & status** on a design, or in a Home widget’s menu, to inspect the real provider state, last sync and error message. Available sources expose **Check live data**, connector connect/reconnect, existing widget/model settings, and inline location setup. Saving a location refreshes the widget through the existing settings-change event. Refresh errors keep the setup editor and saved coordinates available for recovery. Local desktop media explains Linux, `busctl`, the same desktop session, MPRIS and capability-limited controls; it does not ask for a Spotify connector when none is used.

Unavailable designs have a setup screen naming the missing integration or controls and their requirements. It explicitly states when implementation is needed and credentials cannot enable the design. These screens provide no fake API-key form, Add action or playback action. Live data checks do not bypass the existing permission gate.
