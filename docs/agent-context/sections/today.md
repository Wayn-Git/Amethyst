# Today

The widget dashboard at `/today`. It is the default landing page and the
composable “whole day on one page” surface.

**Verified 2026-10-31 · commit `3c363b7` · dirty working tree.**

## Entry points

| Layer | Path |
|---|---|
| View | `frontend/src/dashboard/Home.jsx` |
| Route | `/today`; `/` redirects here |
| Layout | `frontend/src/dashboard/layout.js` |
| Widget map | `frontend/src/dashboard/registry.js` |
| Backend API | `backend/dashboard/router.py` under `/api` |
| Widget registry | `backend/dashboard/registry.py` |
| Widget service | `backend/dashboard/service.py` |

Do not confuse this with `frontend/src/views/Today.jsx` and
`frontend/src/views/today/`. That older Today page is not referenced by the
router. It still calls `/api/today/*`, which remains a separate tracked-items
surface (`backend/api/today.py`). Treat both as legacy until a change explicitly
targets them.

## Layout model

- `layout.js` groups widgets into `glance`, `needs-you`, `tasks`, `library`,
  `dashboard` and system groups.
- A layout is `{ widgets: [{ id, size, height, design? }] }`.
- Modes are named (`default` and others) and stored per mode.
- Defaults are generated by `morningLayout` when no saved layout exists.
- Sizes are declared per manifest (`s`, `m`, `l`). The server rejects a size the
  manifest does not allow (422).
- Editing supports drag reorder, resize, remove, add, fit-to-suggested and
  keyboard move. Changes are saved through `PUT /api/layout?mode=...`.
- Quiet hours pause refresh. Settings are stored through the `dash.quiet`
  widget settings endpoint.

## Data flow

1. `GET /api/widgets` returns validated manifests plus the JSON Schema.
2. `GET /api/layout?mode=...` returns the saved layout.
3. Each widget calls `GET /api/widgets/{id}/data`.
4. The server returns the cached payload immediately and schedules a refresh in
   the background (`schedule`).
5. `POST /api/widgets/{id}/refresh` forces a refresh.
6. Providers write the new payload to the dashboard cache.
7. The client polls per the manifest's `refresh` mode. `poll` requires
   `interval_s`; the schema enforces it.

Refresh is bounded by a semaphore of four. Failures set per-widget backoff and
keep the last good payload. Quiet hours suppress refresh.

## Widget sources

| Source | Meaning |
|---|---|
| `local` | Computed from local database, files or system state |
| `library` | Library items, tags, reading queue |
| `composio` | A connected toolkit, declared with `toolkit` |

A manifest may declare `requires: ["connector:<slug>"]`. The UI uses this to
disable or explain a widget instead of showing an empty box.

Actions are declared in the manifest. `gate: true` means the action goes through
confirmation. Actions are dispatched at
`POST /api/widgets/{id}/actions/{action}`.

### Glance widgets and Playground Loop

Glance widgets (`glance.air`, `glance.sun`, `glance.weather`, `glance.travel`, `glance.next-event`) render via `@tugan/widgets` `WidgetRenderer` using exact templates generated from `widgets.gan.dev/playground` per `docs/widget-playground/WIDGET_LOOP.md`. Artifacts live in `widgets/<widget-id>/` (`template.txt`, `data.fixture.json`, `meta.json`, `wiring.md`), and frontend adapters in `frontend/src/dashboard/widgets/` map live backend payloads to the playground data contracts with zero runtime mock data.


## Adding a widget

1. Add a manifest in `backend/dashboard/registry.py` using the helpers
   (`manifest`, `need_manifest`, `task_manifest`, `library_manifest`) or a full
   dict.
2. Add a provider under `backend/dashboard/` and wire it into
   `service.local_provider` or the connector path.
3. Add the renderer under `frontend/src/dashboard/widgets/` and register it in
   `frontend/src/dashboard/registry.js`.
4. Add the widget to the appropriate default group in `layout.js`.
5. If it has settings, add a settings model in `backend/dashboard/router.py`.
6. Run `python scripts/check-widget-map.py`.
7. Update [components/widget-system.md](../components/widget-system.md).

Manifest rules:

- `id` must be stable; layouts and cache rows key on it.
- `sizes` must include every size the UI may request.
- `refresh.mode == "poll"` requires `interval_s`.
- `empty` must say something useful.
- Invalid manifests are disabled, not fatal.

## Modification guide

| Change | Touch |
|---|---|
| Change default layout | `frontend/src/dashboard/layout.js` |
| Change grid behaviour | `Home.jsx`, `components/widgets/` |
| Change cache policy | `backend/dashboard/service.py`, `store.py` |
| Change a widget's data | its provider in `backend/dashboard/` |
| Add an action | manifest `actions`, router action handler |
| Change quiet hours | `service.quiet_active`, `dash.quiet` settings |
| Change the Today API (legacy) | `backend/api/today.py`, `frontend/src/views/Today.jsx` |

Do not compute widget data in the browser when a provider exists. The server
owns source access, connector auth and caching.

## Known issues

- The legacy `views/Today.jsx` tree is dead code from the router's perspective
  but still imports `/api/today/*`. Removing it requires deciding whether the
  tracked-items API is still a product surface.
- `/api/today/*` and `/api/widgets/*` are two different systems. A change to
  “Today” must state which one it means.
- Widget refresh is best-effort. A source failure shows the last payload with a
  stale/error state, not an exception.
- The dashboard registry is large. Keep frontend and backend ids in lockstep;
  a missing renderer produces an empty card, not a build error.
