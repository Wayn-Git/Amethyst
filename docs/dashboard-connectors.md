# Home connector layer

`task.agenda`, `dev.appeal`, and `sys.connectors` share `backend/dashboard/connectors.py`; there is no second execution client. The machine reader allowlists the two existing read operations, checks the manifest toolkit, enabled access, account health, registered MCP tool and low risk, then passes the permission gate with a callback that refuses approval prompts. Router, proxy, workbench and write tools cannot enter this reader. Existing interactive agent writes retain the registry's approval path.

Home Connect Links reuse `ComposioService.initiate_connection` with explicit read-only OAuth scopes. It selects or creates a scoped managed-auth config and generates a hosted Link; failure cannot fall back to broader scopes. Other existing Connected apps features keep their existing authorization flow. Existing accounts retain their previously granted scopes until reconnected. GitHub's read-only OAuth scopes cover user/organization metadata, not private repository contents. Toolkits without a reviewed read-only scope set expose health but disable Home's Connect button; use the existing Connected apps settings for those integrations. No write-scope upgrade feature was added.

Health stores toolkit, last successful reader call, failure count, retry deadline and pending reconnect metadata in SQLite. An expired account stays in “needs reconnect” until an active replacement account or an updated active account proves a pending sign-in completed. Creating a link alone never clears that state. New calendar connections enable the already-declared toolkit through the existing session updater.

Reads serialize per database and connector. HTTP 429/tool rate-limit errors back off exponentially from 30 seconds to 15 minutes; numeric Retry-After can extend that wait (bounded to one day). Three consecutive other execution failures open that connector's circuit for 60 seconds. After the deadline one serialized probe can reset the circuit on success. Manual refresh bypasses widget freshness, but cannot bypass a source cooldown. Connection discovery retains the existing Composio account cache/backoff.

The existing widget service/store and `useWidget` hook own stale-while-revalidate, single-flight refresh and manifest-interval polling. Raw results exist only during projection. Calendar cache contains projected event fields; support cases retain the existing minimal reply projection. Health cache contains status metadata only. Tokens, Connect Links and raw source responses are never placed in widget caches. Connect Links remain temporary component state and disappear on reload. All reader attempts (including denials/errors), connection-health reads and Connect Link operations enter `execution_logs`, the same repository read by `agent.audit` and the existing tool-call/privacy log. No separate audit store or unshipped `sys.privacy` widget was added.

## Data path and due diligence (2026-10-24)

The browser opens Composio's hosted HTTPS Connect Link; OAuth credentials are handled by Composio. Home sends allowlisted tool arguments through the existing hosted Composio MCP transport. Composio calls the provider and returns data to the local process; the provider projects required fields into the local SQLite widget cache and browser cache. The Home reader does not send responses to an LLM. Existing support-case follow-up generation remains its separate explicit drafting action. Audits record toolkit/widget identity, decision and outcome, not mail bodies, OAuth credentials or raw responses. Read-only access still exposes the requested data to Composio.

Reviewed the published [May 2026 security incident](https://composio.dev/blog/composio-may-2026-security-incident), [April 28 trigger outage](https://landing.composio.dev/blog/incident-report-april-28), and [February 9 authentication incident](https://composio.dev/blog/incident-report-february-9-2026). May's disclosure includes credential compromise affecting GitHub and Gmail; read-only scopes limit modification rights but do not remove confidentiality risk. April's trigger processing/database outage and February's managed-auth disruption reinforce keeping local projections, stale states, reconnect and bounded retries. Live OAuth and trigger delivery were not exercised against user accounts.

Scope configuration follows Composio's [managed-auth scope documentation](https://docs.composio.dev/docs/authentication/controlling-scopes). The official [GitLab catalogue](https://composio.dev/toolkits/gitlab) lists the toolkit. SDK subscription support is documented for local outbound WebSockets; live event delivery remains an open check in spec section 13. Home continues polling without requiring a tunnel.
